# 🎲 Настолка — интерактивная веб-игра

Фанатская реализация настольной игры Настолка из шоу Шальнова и Бебуришвили
(канал Medium Sport). Две команды, кубик с 4 способами объяснения (словами,
песнями, рисунком и жестами) и счёт по очкам.

> ⚠️ Это неофициальный фан-проект.

---

## 🎮 Как играть

1. Откройте сайт на телефоне — передавайте его по кругу.
2. На стартовом экране настройте **2, 3 или 4 команды** (имя, цвет, эмодзи),
   **цель по очкам** (5 / 10 / 15 / 20 / 30) и **время на раунд** (30 / 45 / 60 / 90 сек).
3. Можно выбрать **категории слов** (по умолчанию все 10: животные, еда,
   профессии, спорт, предметы, места, природа, кино, абстракции, быт).
4. Можно выбрать **сложность слов**: Лёгкие / Средние / Сложные (по умолчанию все).
5. Можно добавить **свои слова** (необязательно) — имена друзей, локальные
   шутки, семейные слова. Они попадут в общий пул с встроенными.
6. Команда, чей ход, нажимает **Бросить кубик** — выпадает способ объяснения.
7. Один игрок из команды смотрит на экран, остальные — отворачиваются.
8. Под словом виден бейдж **За ответ: X очков** — это сумма за способ и сложность.
9. При желании используйте **фишки** (кнопки под словом): ×2 для удвоения
   очков, +10 сек / +5 сек для добавки времени.
10. Открывайте слово → объясняйте выбранным способом → команда угадывает.
11. **Угадали!** = начисляются очки (с учётом ×2), **Пропустить** = 0 очков.
12. Слишком сложное слово? Жмите **Заменить слово** под кнопками (без штрафа).
13. Нужно обсудить спор? Жмите **Пауза** — таймер остановится, слово скроется.
14. Выпал способ **Рисунком** — рисуйте прямо на холсте под словом
    (8 цветов, 3 толщины кисти, кнопка Очистить).
15. Первая команда, набравшая заданное число очков, побеждает. 🎉

## 🏆 Система очков

Очки за ответ = **способ** + **сложность** (× множитель, если активирован ×2).

| Способ | Очки | Сложность | Очки |
| --- | ---: | --- | ---: |
| 🗣️ Словами | 1 | 🟢 Лёгкое | 1 |
| 🎵 Песнями | 2 | 🟡 Среднее | 2 |
| 🎨 Рисунком | 2 | 🔴 Сложное | 3 |
| 🤟 Жестами | 3 | | |

**Примеры:**

- Словами + Лёгкое = 1 + 1 = **2 очка**
- Жестами + Среднее = 3 + 2 = **5 очков**
- Жестами + Сложное + ×2 = (3 + 3) × 2 = **12 очков** 🚀

## 🎯 Фишки команды (4 на всю игру)

Каждая команда получает набор из **4 фишек** — используйте их стратегически!

| Фишка | Кол-во | Когда использовать |
| --- | ---: | --- |
| **×2** | 2 шт. | Активируется до нажатия Угадали! — удваивает очки за текущий раунд. |
| **+10 сек** | 1 шт. | Добавляет 10 секунд к таймеру во время раунда. |
| **+5 сек** | 1 шт. | Добавляет 5 секунд к таймеру во время раунда. |

На карточке команды всегда видно сколько осталось фишек. Фишки тратятся
только когда вы их используете, и не восстанавливаются до конца игры.

**Стратегический совет:** ×2 выгоднее всего на способе Жестами (3 очка)
со Сложным словом (3 очка) — итого (3 + 3) × 2 = **12 очков**!

## ✨ Дополнительные возможности

- 👥 **2–4 команды** — выбирайте число команд на старте (2, 3 или 4).
  Ходы переходят по кругу: А → Б → В → Г → А → ...
- 🌍 **i18n (RU/EN)** — переключатель языка в шапке (иконка 🌐). Запоминается.
  Базовый перевод интерфейса (шапка, навигация); полный перевод в разработке.
- 📡 **Мультиплеер через WebSocket** — играйте на двух устройствах! Создайте
  комнату → получите код → второй игрок вводит код → состояние игры
  синхронизируется автоматически. Кнопка 📡 в шапке. **Требует запущенного
  mini-service** (см. раздел Мультиплеер ниже).
- 🏷️ **Фильтр по категориям** — выбирайте только нужные категории слов
  (животные, еда, кино и т.д.) или играйте со всеми сразу.
- 🎯 **Сложность слов** — 3 уровня: Лёгкие / Средние / Сложные.
  Выпадает только выбранная сложность (бейдж показывается на слове).
- 🏆 **Система очков** — способ + сложность (×2 при активации фишки).
- 🎯 **Фишки команды** — 2× ×2, 1× +10 сек, 1× +5 сек на всю игру.
  Каждая фишка имеет **уникальный звук активации**.
- 🎲 **Кража хода** — в начале игры случайно одной команде выдаётся карточка
  Кража хода (видна вверху страницы как заметка). Один раз за игру команда
  может вместо Передать ход нажать Кража хода и сыграть ещё один раунд подряд.
- 🎉 **Анимация начисления очков** — на экране Угадали! большое анимированное
  +X очков. Очки ≥10 — с золотым градиентом, <10 — зелёным.
- 📝 **Свои слова** — добавьте до 4000 символов своих слов (одно в строке).
- 🎨 **Холст для рисования** — когда выпал способ Рисунком, под словом
  появляется холст. Рисуйте пальцем или мышью, 8 цветов, 3 толщины.
- ⏸️ **Пауза** — остановите раунд, не теряя время. Слово скроется.
- 🔊 **Звуковые эффекты** — кубик, тик таймера, фишки, фанфары победы.
- 🌗 **Тёмная тема** — переключается кнопкой в шапке.
- 💾 **Сохранение состояния и настроек** — игра не теряется при перезагрузке.
- 📊 **Статистика игры** — на финальном экране или через шапку: счёт, % успеха
  по командам и способам, лента всех сыгранных раундов с очками.
- 🏆 **Достижения** — глобальная статистика за все сессии: сыграно игр,
  **Σ всего очков**, угадано/пропущено слов, замен, **⚡ лучший раунд**,
  % успеха, рекорды (самая длинная игра, лучший счёт, лучший раунд,
  среднее за игру), последняя дата игры.
- 📤 **Поделиться** — кнопка в шапке открывает системный Share API
  (на телефоне) или копирует ссылку в буфер обмена (на десктопе).
- 📱 **PWA** — сайт устанавливается на телефон как приложение.
- 🔄 **Замена слова** — если выпало слишком сложное слово, его можно заменить
  одним нажатием (без штрафа).
- 🗺️ **Игровая доска** — плавающая панель справа (кнопка › у края экрана):
  доска в стиле «Монополии», фишки команд двигаются по клеткам вслед за очками,
  с анимацией пошагового хода, звуками шагов/вех/финиша, короной лидера,
  мини-историей последних ходов и прогресс-барами до финиша.
- ⏱️ **Отсчёт 3-2-1-Старт!** — перед началом раунда полноэкранный отсчёт,
  чтобы все успели отвернуться от экрана.
- ↩️ **Отмена раунда** — кнопка «Отменить раунд» на экране результата
  откатывает очки, историю и израсходованные фишки.
- ✨ **Плавающие «+N»** — полноэкранная всплывашка с очками и эмодзи команды
  за каждое угаданное слово + маленькое конфетти.
- 🏅 **Лучший раунд (MVP)** — на финальном экране показывается самое
  «дорогое» слово игры.
- 📳 **Вибрация (haptics)** — тактильная отдача на телефоне: бросок, очки,
  пропуск, фишки, победа, тики таймера. Включается в ⚙️ Настройках.
- ⚙️ **Настройки** — диалог в шапке: вкл/выкл звук и вибрацию (запоминается).
- 👆 **Свайпы** — на телефоне: свайп вправо = Угадали, влево = Пропустить.

## 📡 Мультиплеер (опционально)

Мультиплеер позволяет играть на двух устройствах одновременно. Состояние игры
синхронизируется автоматически через WebSocket.

### Запуск mini-service

Мультиплеер требует отдельного WebSocket-сервера. В репозитории он уже есть
в `mini-services/nastolka-multiplayer/`. Чтобы запустить:

```bash
bun run mp          # из корня проекта (быстрее всего)
# или вручную:
cd mini-services/nastolka-multiplayer
bun install         # первый раз
bun run dev
# → "Nastolka WebSocket server on port 3003"
```

Сервер слушает на порту **3003** (переопределяется переменной `MP_PORT`).
Оставьте его работать в отдельном терминале.

### Автозапуск mini-service

В `dev.sh` / `dev.ps1` уже есть автозапуск mini-service при старте dev-сервера:

```bash
bash dev.sh          # Linux / macOS / Git Bash: Next.js (3000) + мультиплеер (3003)
```

```powershell
.\dev.ps1            # Windows PowerShell: то же самое
.\dev.ps1 -NoMp      # только Next.js, без мультиплеера
```

Скрипты сами ставят зависимости mini-service, стартуют его в фоне, проверяют
порт и корректно останавливают всё при выходе (Ctrl+C). Если mini-service не
поднялся автоматически, запустите вручную:

```bash
bash .zscripts/start-multiplayer.sh
# или из корня: bun run mp
```

### Логирование подключений

Mini-service записывает подключения, входы в комнаты и отключения в
`logs/multiplayer.log` в формате JSONL. В журнал попадают время, IP-адрес,
идентификатор сокета и код комнаты. Файлы `*.log` исключены из Git и не
публикуются в репозитории.

При работе за reverse proxy адрес берётся из `X-Forwarded-For` или `X-Real-IP`

Если proxy не должен считаться доверенным, запустите service с
`MP_TRUST_PROXY=false`

### Логирование API

Next.js записывает структурированные JSON-события `api_request` в stdout для
каждого запроса к `/api/*`. В событии есть время, метод, путь, IP, страна и
город (если их передал reverse proxy/CDN), тип устройства, ОС, браузер,
User-Agent, язык, referer и host. Журнал можно смотреть в логах контейнера
Amvera/Docker и передавать в выбранную систему сбора логов.

MAC-адрес клиента в HTTP-запросе недоступен: он не покидает локальную сеть.
Поэтому поле `macAddress` всегда равно `null`, а не содержит выдуманное
значение. Геолокация также не вычисляется приложением самостоятельно и
появится только при наличии заголовков от CDN или reverse proxy.

Путь можно изменить через `MP_LOG_FILE`

### Использование мультиплеера

1. **На устройстве A:** откройте сайт → нажмите 📡 в шапке → Создать комнату
2. Получите 4-значный код (например, `PNXE`)
3. На устройстве B: откройте тот же URL → нажмите 📡 → Присоединиться по коду → введите `PNXE`
4. Любые действия на устройстве A автоматически появляются на B (и наоборот)

**Игра телефон + планшет в одной Wi-Fi сети:** dev-сервер запускается с `-H 0.0.0.0`
(доступен по LAN). Скрипты `dev.sh` / `dev.ps1` сами показывают адрес вида
`http://192.168.x.x:3000` — откройте его на обоих устройствах. Клиент сам найдёт
WebSocket-сервер по IP компьютера (порт 3003). Если не подключается — разрешите
порты 3000 и 3003 в фаерволе (подробности в `RUN.md`).

### Деплой на Amvera

**Мультиплеер на Amvera требует двух проектов:**

- **Основной** (этот репозиторий) — Next.js на порту 3000
- **Mini-service** (`mini-services/nastolka-multiplayer`) — отдельный проект
  Node.js/Bun на порту 3003 (можно использовать секцию `run.containerPort: 3003`
  в `amvera.yml`)

Альтернатива — для мультиплеера не нужен отдельный процесс, если игра
используется на одном устройстве (по кругу). Просто не нажимайте 📡 в шапке.

### Если не подключается

- Сервер не ответил за 15 сек → mini-service не запущен (проверьте `bun run dev` в `mini-services/nastolka-multiplayer/`)
- xhr poll error → порт 3003 недоступен (CORS, фаервол, или браузер на другом устройстве не в одной сети)
- server error → что-то с прокси/сетью между браузером и сервером

## 🛠 Технологии

- **Next.js 16** (App Router) + **TypeScript 5**
- **Tailwind CSS 4** + **shadcn/ui**
- **Framer Motion** для анимаций кубика и переходов
- **canvas-confetti** для салюта при победе
- Состояние игры — `useReducer` с конечным автоматом фаз:
  `setup → ready → rolling → method → task → playing → round_end → game_over`

Банк из ~120 русских слов в 10 категориях (животные, еда, профессии, спорт,
предметы, места, природа, кино, абстракции, быт). Слова не повторяются в
течение сессии (до 30 последних слов).

### Автоотправка в репозитории

Чтобы после каждого коммита автоматически отправлять текущую ветку во все
настроенные Git-репозитории, один раз установите hook:

```bash
npm run hooks:install
```

После этого hook `post-commit` запускает тот же скрипт, что и команда:

```bash
npm run push:all
```

Скрипт отправляет текущую ветку в каждый remote (`origin`, `amvera` и другие).
Если один из репозиториев недоступен, остальные всё равно проверяются, а hook
завершается с ошибкой. Автоотправка не выполняется в режиме detached HEAD.

Для разовой отправки без коммита используйте `npm run push:all`. Чтобы вернуть
стандартный каталог `.git/hooks`, выполните `npm run hooks:uninstall`.


## ☁️ Деплой на Amvera

Проект подготовлен для деплоя на [Amvera Cloud](https://cloud.amvera.ru/).
Поддерживаются **два способа** — выберите любой.

### Подготовка (общая для обоих способов)

1. Зарегистрируйтесь на [Amvera Cloud](https://cloud.amvera.ru/).
2. Создайте новый проект, выберите тип **Подключить репозиторий**
   (или используйте Amvera как origin и пушьте напрямую).
3. Подключите GitHub/GitLab/Bitbucket **ИЛИ** используйте Amvera как
   основной репозиторий (через `git remote add amvera ...`).

### Способ A — через Docker (рекомендуется) 🐳

В корне уже есть нужные файлы:

- **`Dockerfile`** — multi-stage сборка Next.js в standalone-режиме
- **`amvera.yml`** — конфигурация для Amvera (environment: docker)

**В настройках проекта на Amvera:**

1. **Среда**: `Docker` (Amvera определит это автоматически по `amvera.yml`)
2. **Порт контейнера**: `3000`
3. **Публичный порт**: `80` (по умолчанию)

**Пуш в `main` автоматически:**

- Соберёт Docker-образ (Node 18 + Next.js standalone)
- Запустит контейнер на порту 3000
- Прокинет публичный URL на порту 80

### Способ B — через Node.js Server (без Docker) 📦

Если Docker по какой-то причине не подходит — можно деплоить как
обычное Node.js-приложение:

1. **Удалите** (или переименуйте) `Dockerfile` и `amvera.yml`.
2. **Переименуйте** `amvera.nodejs.yml` → `amvera.yml`.
3. **Создайте `package-lock.json`** (важно для Amvera):

```bash
rm -rf node_modules
npm install --legacy-peer-deps
```

1. **Закоммитьте** `package-lock.json` в репозиторий.
2. На Amvera укажите:
   - **Среда**: `Node.JS Server`
   - **Версия Node.js**: `18`

В этом режиме Amvera:

- Запустит `npm install && npm run build` (фаза сборки)
- Скопирует `.next/standalone`, `.next/static`, `public` в рабочую папку
- Запустит `node server.js` на порту 3000

### Переменные окружения

Проект работает **без обязательных переменных окружения**. Все данные игры
хранятся в localStorage браузера. Если понадобится — на Amvera в разделе
**Переменные** можно добавить:

| Переменная | Описание | По умолчанию |
| --- | --- | --- |
| `PORT` | Порт сервера | `3000` |
| `NODE_ENV` | Окружение (production) | `production` |
