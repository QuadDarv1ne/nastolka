# 🚀 Инструкция по запуску «Настолки»

Полное руководство по запуску игры: локально (Bun / npm / Windows), через Docker,
мультиплеер, и деплой на Amvera Cloud.

> **TL;DR** — минимальный запуск:
> ```bash
> bun install && bun run dev
> # → откройте http://localhost:3000
> ```

---

## 📦 Шаг 0. Получить исходники

```bash
# из zip-архива:
unzip nastolka.zip -d nastolka

# из tar.gz:
tar -xzf nastolka.tar.gz -C nastolka/

# клонированием:
git clone <url-репозитория> nastolka

cd nastolka
```

## 💻 Локальный запуск

### Требования

- **Node.js 18.17+** (рекомендуется 20+), **или** [Bun](https://bun.sh) 1.0+ — быстрее и проще
- Для мультиплеера — Bun или Node (см. раздел «Мультиплеер»)

### Способ 1. Bun (рекомендуется) 🥟

```bash
# Установить зависимости
bun install

# Запустить dev-сервер
bun run dev
```

Откройте в браузере: **http://localhost:3000**

### Способ 2. npm (если нет Bun)

```bash
# Установить зависимости
npm install --legacy-peer-deps   # флаг обязателен из-за peer-зависимостей

# Запустить dev-сервер
npm run dev
```

Откройте: **http://localhost:3000**

> **Windows:** команды одинаковы в PowerShell и CMD. Если `npm run start`
> ругается на `NODE_ENV=production`, запустите так:
> ```powershell
> $env:NODE_ENV="production"; node .next/standalone/server.js
> ```

### Способ 3. Production-сборка (как на хостинге)

```bash
npm install --legacy-peer-deps
npm run build       # собирает standalone-сервер в .next/standalone
npm run start       # запускает на http://localhost:3000
```

> `npm run build` использует `cp -r` (bash). На Windows запускайте через Git Bash
> или WSL, либо используйте Docker (способ 4).

### Способ 4. Docker (как сделает Amvera)

```bash
# Собрать образ
docker build -t nastolka .

# Запустить контейнер на порту 3000
docker run -d -p 3000:3000 --name nastolka nastolka
```

Откройте: **http://localhost:3000**

Проверка живости: откройте `http://localhost:3000/api/health` — вернёт
`{"status":"ok",...}`.

Остановка: `docker stop nastolka && docker rm nastolka`

## ☁️ Деплой на Amvera Cloud

### Шаг 1. Подготовка репозитория

```bash
cd nastolka
git init
git add .
git commit -m "feat: «Настолка» — board game web app"
```

### Шаг 2. Загрузка на Amvera

**Вариант A — через GitHub (рекомендуется):**

1. Запушьте репозиторий на GitHub/GitLab/Bitbucket:
   ```bash
   git remote add origin git@github.com:<user>/nastolka.git
   git push -u origin main
   ```
2. На [cloud.amvera.ru](https://cloud.amvera.ru/) создайте проект
3. Выберите **«Подключить репозиторий»** → авторизуйтесь → выберите репозиторий

**Вариант B — Amvera как origin:**

```bash
# В настройках проекта на Amvera скопируйте URL репозитория
git remote add amvera https://git.amvera.ru/<your-login>/nastolka.git
git push -u amvera main
```

### Шаг 3. Настройка проекта на Amvera

В интерфейсе Amvera укажите:
- **Среда**: `Docker` (определится автоматически по `amvera.yml`)
- **Порт контейнера**: `3000`
- **Публичный порт**: `80` (по умолчанию)

### Шаг 4. Запуск

Amvera автоматически:
1. Считает `amvera.yml` из корня репозитория
2. Соберёт Docker-образ через `Dockerfile` (Node 18 + Next.js standalone)
3. Запустит контейнер на порту 3000
4. Прокинет публичный URL (вида `https://nastolka.cloud.amvera.ru`)

Каждый пуш в `main` автоматически пересоберёт и передеплоит приложение.

### ⚠️ Если возникли проблемы на Amvera

| Симптом | Решение |
|---|---|
| `npm ci` ошибка на сборке | Удалите `bun.lock` и создайте `package-lock.json`: `npm install --legacy-peer-deps`. Закоммитьте package-lock.json. |
| 502 Bad Gateway | Проверьте логи Amvera. Убедитесь, что `containerPort: 3000` в `amvera.yml` |
| Белый экран | Проверьте, что `output: 'standalone'` включён в `next.config.ts` (уже включено) |
| Ошибки `sharp` | Multi-stage Dockerfile уже это учитывает (alpine + libc6-compat) |

### Альтернатива — Node.JS Server без Docker

Если Docker по какой-то причине не нужен:
1. Удалите `Dockerfile` и `amvera.yml`
2. Переименуйте `amvera.nodejs.yml` → `amvera.yml`
3. Создайте `package-lock.json`:
   ```bash
   rm -rf node_modules bun.lock
   npm install --legacy-peer-deps
   ```
4. Закоммитьте `package-lock.json`
5. На Amvera выберите **среду**: `Node.JS Server`, **версия Node.js**: `18`

## 🎮 Как играть (краткая памятка)

1. Откройте сайт на телефоне — передавайте его по кругу
2. На стартовом экране настройте **2, 3 или 4 команды** (имя, цвет, эмодзи),
   **цель по очкам** (5 / 10 / 15 / 20 / 30) и **время на раунд**, при желании
   выберите категории слов, сложность (Лёгкие / Средние / Сложные) и добавьте
   свои слова
3. Команда, чей ход, жмёт **«Бросить кубик»** — выпадет способ объяснения
4. Один игрок из команды смотрит на экран, остальные — отворачиваются
5. Под словом виден бейдж **«За ответ: X очков»** (способ + сложность, ×2 если фишка)
6. Можно использовать фишки: **×2** (удвоить очки), **+10 сек**, **+5 сек**
7. Жмите **«Показать слово»** → объясняйте → команда угадывает
8. **«Угадали!»** = очки начисляются, **«Пропустить»** = 0 очков
9. Слишком сложное слово? Жмите **«Заменить слово»** (без штрафа)
10. Спор? Жмите **«Пауза»** — таймер остановится, слово скроется
11. Выпал способ **«Рисунком»** — под словом появится холст. Рисуйте пальцем
    или мышью (8 цветов, 3 толщины, кнопка «Очистить»).
12. Первая команда, набравшая заданное число очков, побеждает 🎉

## 🏆 Система очков

| Способ | Очки | | Сложность | Очки |
|---|---|---|---|---|
| Словами | 1 | | Лёгкое | 1 |
| Песнями | 2 | | Среднее | 2 |
| Рисунком | 2 | | Сложное | 3 |
| Жестами | 3 | | | |

**Примеры:** «Словами» + «Лёгкое» = 2 очка · «Жестами» + «Сложное» + ×2 = 12 очков

## 🎯 Фишки команды (4 на всю игру)

- **×2 (2 шт.)** — удвоить очки за раунд (активируется до «Угадали!»)
- **+10 сек (1 шт.)** — добавить 10 секунд во время раунда
- **+5 сек (1 шт.)** — добавить 5 секунд во время раунда

## 📡 Мультиплеер (опционально)

Мультиплеер — игра на двух устройствах одновременно с автосинхронизацией
состояния. Требует запущенного WebSocket-сервера из `mini-services/nastolka-multiplayer/`.

### Запуск mini-сервиса

**Из корня проекта (проще всего):**

```bash
bun run mp          # dev-режим с hot-reload → порт 3003
```

**Или вручную:**

```bash
cd mini-services/nastolka-multiplayer
bun install
bun run dev         # → "Nastolka WebSocket server on port 3003"
```

Оставьте процесс работать в отдельном терминале.

**Свой порт** (если 3003 занят):

```bash
MP_PORT=3004 bun run mp
```

### Как играть по сети

1. На устройстве A: откройте сайт → 📡 в шапке → **«Создать комнату»**
2. Получите 4-значный код (например, `PNXE`)
3. На устройстве B: тот же URL → 📡 → **«Присоединиться по коду»** → введите `PNXE`
4. Всё, что происходит на A, автоматически отображается на B (и наоборот)

> Оба устройства должны быть в одной сети (Wi-Fi), а порт 3003 — доступен
> с устройства B. Если играете через интернет — запустите mini-сервис
> на публичном хостинге (Amvera, см. ниже).

### Мультиплеер на Amvera

Мультиплеер требует **двух проектов** на Amvera:

- **Основной** (этот репозиторий) — Next.js, порт 3000
- **Mini-service** (`mini-services/nastolka-multiplayer`) — отдельный проект,
  порт 3003 (укажите `run.containerPort: 3003` в его `amvera.yml`)

### Диагностика мультиплеера

| Симптом | Причина / решение |
|---|---|
| «Сервер не ответил за 15 сек» | mini-сервис не запущен — проверьте `bun run mp` |
| «xhr poll error» | Порт 3003 недоступен: фаервол, разные сети, CORS |
| «server error» | Проблема прокси/сети между браузером и сервером |

Если мультиплеер не нужен — просто не нажимайте 📡 в шапке.

## 🔧 Переменные окружения

Проект работает **без обязательных переменных** — все данные игры в localStorage.

| Переменная | Где | По умолчанию | Описание |
|---|---|---|---|
| `PORT` | Next.js / Docker | `3000` | Порт основного сервера |
| `MP_PORT` | mini-сервис | `3003` | Порт WebSocket-сервера мультиплеера |
| `NODE_ENV` | prod-сборка | — | `production` при запуске standalone |

## ❗ Возможные проблемы

| Симптом | Решение |
|---|---|
| `npm ci` ошибка на сборке | Удалите `bun.lock`, создайте `package-lock.json`: `npm install --legacy-peer-deps`, закоммитьте |
| 502 Bad Gateway | Проверьте логи Amvera. Убедитесь, что `containerPort: 3000` в `amvera.yml` |
| Белый экран | Проверьте, что `output: 'standalone'` включён в `next.config.ts` (уже включено) |
| Ошибки `sharp` | Multi-stage Dockerfile уже это учитывает (alpine + libc6-compat) |
| `cp -r` не работает на Windows | Собирайте через Docker или Git Bash/WSL |
| Порт 3000 занят | `PORT=3001 bun run dev` или измените порт в `package.json` |
| Порт 3003 занят (мультиплеер) | `MP_PORT=3004 bun run mp` |
| EPERM/ошибки установки на Windows | Запустите терминал от администратора или используйте Bun |
